Candidate 01

Clarify the task-manager fixture’s responsibilities

Worth exploring ports & adapters

internal/taskmanager/fixture.go · ownership.go · cmd/taskmanager/main.go

Before · responsibilities share the fixture

After · one fixture module, clearer internal ownership

Problem

The fixture owns both task-manager domain setup and runtime-store lifecycle, so following a domain operation can cross into runtime coordination and same-file persistence concerns.

Solution

Make the fixture’s domain operations and runtime lifecycle legible as distinct internal responsibilities, while keeping their same-file atomic commit behavior together.

Benefits

  • locality: domain rules stay findable
  • leverage: CLI uses one fixture seam
  • tests exercise same-file behavior intact

Candidate 03

Localize recovery paths inside reconciliation

Speculative in-process

runtime/coordinator.go · runtime/worker.go · internal/runtimecontract/

Before · one reconciliation path spans many cases

flowchart TB
  A[Coordinator reconciliation] --> B[Acquire transition lease]
  B --> C{Persisted state}
  C --> D[Dispatch or wait]
  C --> E[Unknown attempt]
  C --> F[Retry / deadline]
  C --> G[Intervention / completion]
  H[Worker activity lease] -. separate claim .-> D
  classDef protocol fill:#fff,stroke:#94a3b8,color:#0f172a;
  class B,C,D,E,F,G,H protocol;

After · protocol ownership stays explicit

Problem

Reconciliation spans lease acquisition, unknown outcomes, retries, deadlines, intervention, and completion, so recovery invariants can be difficult to locate in the central protocol path.

Solution

Consider making recovery cases easier to follow within the coordinator implementation while preserving coordinator protocol ownership and the separate worker activity seam.

Benefits

  • locality: recovery decisions easier to verify
  • tests keep using protocol contracts
  • no new seam or adapter implied
ADR-0007: Keep reconciliation and transition progression in the coordinator; workers own separately fenced activity leases. This candidate stays within that decision and does not propose moving protocol ownership.

Top recommendation

Clarify the task-manager fixture’s responsibilities

It offers the clearest tractable question: improve locality between domain operations and runtime setup without weakening the documented same-file atomicity guarantee. Start by exploring where that internal split improves depth rather than adding another shallow module.
