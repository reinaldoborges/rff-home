After · the same contracts test two adapters

Problem

The shared contracts depend on generic runtime ports, but SQLite runs the broad suites while the in-memory test store covers acceptance only, so most interface behavior has one tested implementation.

Solution

Explore extending an implementation-independent test adapter so the relevant shared contract suites can run against it as well as SQLite; leave production ports unchanged.

Benefits

  • leverage: one contract, two adapters
  • locality: behavior stays in contracts
  • tests exercise the runtime seam
Evidence: runtime and internal/runtimecontract do not import SQLite; SQLite has its own persisted representation/codecs. internal/taskmanager/migration.go does use sqlite.StringCodec, but that dependency is in task-manager fixture migration code, not in the generic runtime contract.
ADR-0004: This candidate supports host-supplied persistence and does not propose changing the typed persistence ports or moving domain ownership.

Top recommendation

Prove adapter substitutability through the shared contract suite

The generic runtime seam already aligns with ADR-0004. Broader contract execution against an independent test adapter would show whether its implementation can vary without changing the interface, while keeping production architecture stable.
